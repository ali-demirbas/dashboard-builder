# dashboard-builder — Repo Rules

These govern the repo and its maintenance workflow, not the skill's runtime behavior. The skill's own behavioral rules (data handling, comparability, evidence grading, output format) live in `skills/dashboard-builder/SKILL.md` and its `references/*.md` — that is the single source of truth for what the skill does, and it is not restated here. Duplicating it into a second file would create exactly the kind of silent-drift risk the skill itself warns against (`kpi-framework.md` §1, session metric registry) — two places that must be kept in sync forever, with no mechanism forcing that.

1. **`SKILL.md` + `references/*.md` + `scripts/README.md` are the source; `dashboard-builder-consolidated.md` is a generated release artifact** (their verbatim concatenation, built by `scripts/build_consolidated.sh`; the `dbcalc` code is not part of it). It is regenerated only on explicit request, never automatically after every reference-file edit. Editing the consolidated file directly instead of its source is a bug, not a shortcut — it will be silently overwritten on the next real regeneration and the edit is lost.
2. **`MAINTENANCE-LEDGER.md` tracks pass/module state and must be updated in the same change that edits a reference file.** A module whose `last_changed_pass` exceeds `last_consolidated_build.pass` means the consolidated file is stale — check this before publishing it, and update the ledger's `last_consolidated_build` block whenever the consolidated file is actually regenerated.
3. **Every metric definition, formula variant, or benchmark added to `kpi-framework.md`, `comparability-rules.md`, or `research/raw/*` carries a verified source** — a fetched vendor doc, a cited paper, or an explicit "unverified, directional only" label. Nothing is added from memory and presented as sourced.
4. **No vendor or third-party-tool attribution in commit messages, `CHANGELOG.md`, `MAINTENANCE-LEDGER.md`, or any shipped doc.** Naming which external AI tool, model, or paid product suggested a change is never appropriate here — books and peer-reviewed research are fine to cite (see rule 3), commercial products and other AI systems are not. This was violated once (a leaked tool-comparison list in an early ledger draft) and was scrubbed; it doesn't recur.
5. **Real account or business data from a live test (a user's actual GA4/Ads/CRM export, actual figures) never enters this repo** — not in an example, not in a test fixture, not in a commit message. Live-test findings are reported to the user in-conversation only. `examples/` and `evals/fixtures/` hold synthetic data only (generated by `evals/fixtures/make_fixtures.py` or written by hand); planted identifiers in fixtures are fake by construction.
6. **`bash scripts/validate.sh` and `python3 -m unittest discover -s tests` pass before a PR merges, and validate.sh again after the consolidated file is regenerated for release.** The unit tests cover the validators, `dbcalc`'s known answers and behavior, the pinned results in `evals/expected/`, and that every `evals/cases/` file's fixtures exist; the behavioral evals (`evals/run_evals.py`) cost real model sessions and are run by hand, never in CI. Between releases the content-staleness check is expected to fail until the consolidated file is regenerated (rule 1). It checks: `SKILL.md` front matter validity; internal link integrity; the `references/` table in `SKILL.md` against what's actually on disk; that `plugin.json` and `marketplace.json` parse; a scan of shipped content (`research/*.md`, `research/raw/*.md`, the test suite) for instruction-like text; consolidated-file staleness by the ledger's pass numbers; and consolidated-file staleness by content — a fresh rebuild via `scripts/build_consolidated.sh` must match the committed `dashboard-builder-consolidated.md` byte for byte. The ledger check reads only module names without a slash, so `scripts/README.md`'s staleness is caught by the content check.
7. **Push discipline follows the user's own global convention**, not this repo specifically: confirm the intended GitHub account before pushing. This repo does not auto-push or auto-deploy on any local change.
